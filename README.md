# Mruthulan's portfolio

Personal portfolio for Senthil Nathan Mruthulan at [mruthulan.com](https://mruthulan.com). A static site (HTML, CSS and JavaScript) hosted on GitHub Pages. The pages are generated by one Python script; there is no other build step.

## Design: Night Edition

One dark ground, off-white type, set a size larger on laptops and up (19px reading text) than on phones. Each kind of text has one face: condensed Archivo capitals for the name, titles and project names; Bricolage Grotesque for big statements (the hero line, leads); Geist for reading text and labels; JetBrains Mono only for proof (routes, file names, the stack, figures like S$3,000). Emphasis is weight and gold, never italics. The signature is a split-flap departures board. Titles are gold (#E8B64C; a deeper #8A6400 on the newsprint panel). Project colour appears in small marks, on the project in focus, and on its case page, where the name and the section headings take the project's colour. The colours: SignalBridge teal, MEANT sky blue, Better Call Bhai yellow, KnowCad violet, Boss Breaker orange.

The homepage reads like a product page, and every project is a full-screen 3D scene: the name, then five projects one by one, then Awards, About and the ending board. It has very few words; every one of them is listed in `docs/superpowers/specs/2026-10-11-3d-homepage-design.md` as changed by `docs/superpowers/specs/2026-10-11-3d-homepage-v2-design.md`.

### Motion

The 3D is one fixed three.js canvas behind the page (`js/3d/stage.js`) showing one world (`js/3d/world.js`): the scenes stand along a camera path whose keyframes, colours and positions are in `js/3d/paths.js`, and the scroll position picks the camera's place on it. The hero, Awards and the ending are page sections: there the camera holds still and the 3D is fitted to the page's own boxes, so it lines up with the words exactly. The lights travel with the camera and take each project's colour. A scene is built when you are within one section of it (its shaders compiled and its textures uploaded a frame at a time first) and freed three sections away. The 3D runs only with WebGL 2, without reduced motion or Save-Data, and on devices with at least 4 GB of memory; otherwise, without JavaScript, or if frames stay slow, every scene shows its still (rendered from the live scene). `?mode=stills` and `?mode=3d` force either.

Scrolling: a mouse wheel and trackpad glide with Lenis (`js/vendor/lenis/`), which still scrolls the real page; touch keeps the phone's own scrolling, and keyboard, links and the scrollbar work as always. One frame loop (`js/lib/ticker.js`) runs, in order, the smooth scroll, the chapters' words and the 3D, so everything drawn in a frame agrees on where the page is; it sleeps when nothing moves. To try the page without the smoothing, add `?smooth=off`; to remove it, delete the Lenis block in `js/home.js`. Every page arrives finished: nothing spins, spells itself out or fades in on load, and nothing moves by itself. Moving between the home page and a case page uses cross-document view transitions where the browser supports them: the project name travels into the case title.

The page answers the pointer: the boards lean and flicker, each chapter's camera turns slightly toward the mouse, and each scene has its own touch (above). Case-page screenshots and the portrait tilt toward the mouse; buttons lean toward it and fill with colour from the side the pointer came in.

Smoothness, measured with real input and a 4× slower CPU on the real GPU (`npm run perf -- desk|phone`): a real mouse wheel down the whole page gives about 3.5–4% slow frames (over 33 ms), no frame over 100 ms (the longest 83 ms), a 99th-percentile scroll jerk of 31–38 px against 100 px for the browser's own wheel scrolling, and no frame where the 3D used a different scroll position from the page; real finger swipes on a phone give about 2% slow frames. The first paint on a slow 4G phone is 1696 ms, against 1912 ms for the page before the redesign (`tests/browser/firstpaint.mjs`). A frame watchdog lowers the resolution, then switches to the stills, if frames stay slow while the page moves.

Under `prefers-reduced-motion: reduce` all of this is off: every scene is its still, there is no smooth scrolling, the hotspot view changes without moving, and nothing moves by itself.

### Rules the design depends on

- No stock imagery. Every photo and screenshot is real and captioned; screenshots use fictional or test data.
- Nothing unconfirmed is published. Where wording is not confirmed it is left out rather than guessed.
- The KnowCad repository and the Autodesk materials are private, so that page has no code link and no product screenshots.
- The MEANT repository is linked nowhere.
- The Better Call Bhai testimonial is the owner's own WhatsApp message, emoji removed and one sentence left out, marked with an ellipsis (`data/content.json` records what was cut).
- The phone number on the résumé is never published.
- The organisers' logos only name where each event was held: no links, no suggestion of endorsement.
- No visible reading text is smaller than 16px.
- On touch screens every standalone link and button is at least 44px tall.
- The SignalBridge event is "Dell InnovateDash 2026" (the finals signage and the proof post); the SignalBridge page notes that Singapore Polytechnic's feature calls it "SP InnovateDash 2026".

## Editing and rebuilding

All page content lives in `design/build_site.py` (project facts, case-page sections, home page) plus `data/content.json` (the About paragraph and the testimonial) and `data/media.json` (image files, alt text, captions and sizes). Never edit the generated HTML.

```
python design/build_site.py
```

This writes `index.html`, the five case pages, `privacy.html` and `404.html`, makes 800px-wide copies of large images for phones (`*-800.webp`; originals are untouched), and stamps the CSS and JS links. It needs Python 3 and Pillow.

The 3D's pieces are made by scripts:

```
python design/build_3d_assets.py     # screen textures, crops and prints from the real captures → assets/3d/
python design/build_name_fonts.py    # each project's name font → assets/fonts/name-*.woff2
npm run vendor:three                 # three.js, bundled and minified → js/vendor/three/
npm run vendor:lenis                 # Lenis, the same way → js/vendor/lenis/
npm run stills -- hero signalbridge boss-breaker better-call-bhai meant knowcad ending   # serve on :8000 first
```

To tune a scene, change its keys in `js/3d/paths.js` (or its objects in `js/3d/chapters/<name>.js`) and take a picture at a moment of its chapter: `node tests/browser/shot.mjs --at=signalbridge:0.42 --out=…` (chapter-local time: -0.4 arriving, 0.42 the payoff; `--at=#awards:0` for a page section; `--size=390x844` for a phone). `node tests/browser/review.mjs --from=0 --to=end --out=….webp` records a scroll.

Tests: `npm install` and `python -m pip install -r design/requirements-dev.txt` once, then `npm test` (pure logic), `python -m pytest tests -q` (what the generator writes; build first), and `npm run smoke` (the page in a browser; serve on :8000). `npm run perf -- desk|phone` checks smoothness with a real wheel and real swipes.

After changing `css/` or `js/`, rebuild with `python design/build_site.py`: it stamps every link and the homepage's import map with a hash of each file, so browsers fetch the new files instead of a cached copy.

## Publishing and domain

Every push to `main` runs `.github/workflows/pages.yml`, which checks the site and publishes it with GitHub Actions (Settings → Pages → Source: GitHub Actions). It rebuilds the pages and fails if they differ from the committed HTML (so the generated pages are never edited by hand), then collects only what the site serves (the HTML pages, `css/`, `js/`, `assets/`, `robots.txt`, `sitemap.xml`) and fails if any link, image or #anchor on them points at nothing. The generator, `design/`, `data/` and notes like this README stay in the repository and off the website. Pull requests run the same checks without publishing. Run them locally with `python design/check_site.py --unchanged` after a build, and `python design/check_site.py .` for the links.

The custom domain is `mruthulan.com` (set in the Pages settings; the `CNAME` file records it). The Namecheap DNS zone should have GitHub Pages' four apex A records and a `www` CNAME to `mru34.github.io`.

## Analytics

The Google Analytics 4 measurement ID is configured in `js/analytics.js`. The question appears as a slim bar once a visitor scrolls into the page, and the tag loads only after they choose **Yes**; the choice is stored in that browser and can be changed on the privacy page. After consent the site sends `case_open`, `resume_click`, `proof_post_click` (with the project), `press_viewer_open`, `press_article_click`, `contact_copy_email`, `contact_open_mail_app`, `contact_open_linkedin` and `contact_open_github`. No names, email addresses or free text are sent.

## Link previews

Each case study shares with its own 1200×630 card (`assets/og/<page>.jpg`); the home page, privacy and 404 use `assets/og/home.jpg`. The cards are drawn from the site's fonts and pictures by `portfolio-tools/card-shots/og.mjs` (outside the repo); re-run it after changing a project's picture, wording or result, then convert the PNGs to JPG and rebuild. Each `og:image` URL carries a hash of the file, so LinkedIn fetches a changed card again. `assets/og-card.jpg` is kept, with the home card's content, for links shared before.

## Fonts

Archivo, Bricolage Grotesque, Geist and JetBrains Mono are served from `assets/fonts/` (latin subsets of the Google Fonts variable files, OFL; see `assets/fonts/LICENSES.txt`). `css/styles.css` declares them and every page preloads Archivo, the name and board font, so the first paint never waits on another domain.

## Résumé

The résumé is built from text by `python design/build_resume.py` (one A4 page; needs reportlab), which writes `assets/Mruthulan-Senthil-Nathan-Resume.pdf` and the same file at the old address, `assets/Senthil-Nathan-Mruthulan-Resume.pdf`, so older links still work. Every line matches what the site says, so change both together. The phone number is never published, so it is not in the script; add it to your own copy for applications.
